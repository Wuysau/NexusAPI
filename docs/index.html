01 / SETUP

快速开始

以下命令在本机运行。NexusAPI 控制台是控制面；真正的模型请求发送到独立 Go 网关。

准备环境

Node.js 24、npm、Docker，以及测试 API 时可用的上游模型账号和密钥。任务监督另需官方 Codex CLI 与独立登录的 Profile。

  1. 克隆并安装 
    git clone https://github.com/Wuysau/NexusAPI.git
cd NexusAPI
npm ci
  2. 创建本地配置

    Windows PowerShell 使用下方命令；macOS/Linux 用 cp .env.example .env.local。编辑 .env.local，设置 DEV_ADMIN_PASSWORD、DEV_VIEWER_PASSWORD；要测网关，还需为 SNAPSHOT_SIGNING_KEY（至少 32 字符）和 GATEWAY_INTERNAL_TOKEN 分别生成随机值。 

    Copy-Item .env.example .env.local

    本地网关推荐使用 APP_BASE_URL=http://127.0.0.1:3000、NEXUS_DESKTOP_ORIGIN=http://127.0.0.1:3000、CONTROL_PLANE_URL=http://127.0.0.1:3000 和 NEXT_PUBLIC_GATEWAY_BASE_URL=http://127.0.0.1:8080/v1。

  3. 启动基础服务并初始化 
    docker compose up -d postgres redis
node --env-file=.env.local scripts/db-migrate.mjs
npm run seed:dev
npm run dev

    Windows 日常启动也可在数据库已就绪时使用 npm run dev:local。控制台默认位于 http://127.0.0.1:3000；用 DEV_ADMIN_EMAIL（默认 dev@nexus.local）及配置的密码登录。

  4. 创建项目

    进入“项目”→“创建项目”，填写名称与实际代码工作目录。工作目录决定后续 Codex 会话用量归属；初次创建不要求已有请求。

安全提醒：.env.local 和真实 API Key 只保存在本机，不要提交到 GitHub。开发种子数据用于演示，不代表真实报价、额度或账单。

02 / VERIFY

三条主流程

先验证最短的 API 链路，再验证本地 Codex，最后配置需要额外 Profile 的任务监督。

01

网关 API：发出第一个真实请求

适合测试上游密钥、路由、模型调用及用量记录。

真实调用会消耗上游额度
  1. 在控制台“渠道管理”中录入上游地址、协议、模型和 API Key，保存后运行连接测试。不要在“我的连接”里仅登记一个 API 连接就期待网关可用。
  2. 在“API 密钥”创建 Nexus 下游密钥。它是调用本地网关的密钥，与上游 API Key 不同。
  3. 另开终端运行 npm run gateway:local；需要本地渠道密钥已保存。先检查 http://127.0.0.1:8080/healthz。
  4. 用下方请求把占位符换成真实 Nexus 密钥和已配置模型。第一段适用于 Bash，第二段适用于 Windows PowerShell；也可通过兼容 OpenAI 的客户端调用。 
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer YOUR_NEXUS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"YOUR_CONFIGURED_MODEL","messages":[{"role":"user","content":"Hello"}],"max_tokens":32}'
$headers = @{ Authorization = "Bearer YOUR_NEXUS_API_KEY" }
$body = @{ model = "YOUR_CONFIGURED_MODEL"; messages = @(@{ role = "user"; content = "Hello" }); max_tokens = 32 } | ConvertTo-Json -Depth 5
Invoke-RestMethod -Uri 'http://127.0.0.1:8080/v1/chat/completions' -Method Post -Headers $headers -ContentType 'application/json' -Body $body
成功信号收到模型响应；“请求日志”出现请求；“用量与计费”显示实际用量。未知价格仍应显示未知。
02

Codex：观察本机订阅使用

适合验证账户状态、官方额度观测和本地会话用量归属。

不经过网关
  1. 在本机通过官方 Codex 完成登录，并确认项目已设置正确的工作目录。
  2. 进入“我的连接”→“添加连接”，选择“OpenAI Codex · 本地订阅观测”；供应商标识保留 openai。
  3. 打开该连接详情，应用 Observer 配置；确认会话目录后点“立即同步”。
  4. 在已配置的项目工作目录中实际运行一次 Codex，再查看项目分析和连接详情。
成功信号连接显示最新账户或额度观测，项目分析出现会话用量。订阅会话不会变成网关 API 请求，也不会产生 Nexus 扣费。

03

任务监督：验证资源选择和切换

适合测试 Coding Agent 的任务、策略、连续性与故障交接。

需独立 Profile
  1. 为每个要测试的账户准备独立 CODEX_HOME，在各 Profile 中分别运行官方 codex login。不要复制认证文件。
  2. 按运维文档创建忽略提交的 config/nexus-supervisor.json，填写实际租户、组织、项目、连接 ID、工作目录和 Profile 路径。
  3. 设置 NEXUS_SUPERVISOR_CONFIG 为配置文件绝对路径，并重启包含 Observer 的本地开发服务。
  4. 在“任务”页为项目配置路由策略与候选连接。下方命令适用于工作目录就是 NexusAPI 仓库的测试；若目标是其他仓库，请按运维文档从该仓库运行 Nexus 脚本的绝对路径。 
npm run nexus -- codex --project PROJECT_ID --goal "完成一个可验证的编程任务" --persist-context
成功信号“任务”页出现任务状态、当前资源与会话；切换时留下原因和历史。要验证自动故障切换，需两个真实可用且有独立额度观测的兼容 Profile。

03 / MODEL

“连接”和“连接器”是什么

区分资源登记、实际执行位置和可用性，能避免配置完成后却无法调用的误解。

连接

资源的登记记录，包含供应商、归属项目、类型和观测状态。添加连接不代表凭据已配置或请求可路由。

渠道

网关 API 的上游地址、模型、凭据和路由配置。要测试 HTTP 模型调用，请从“渠道管理”开始。

连接器

设计上是运行在本机或私有网络、代为执行并报告状态的程序。当前“本地连接器”“私有网络连接器”选项主要用于登记，不会在添加时自动安装运行器。

Codex Profile

任务监督使用的独立 Codex 配置与登录目录。它不同于普通网关渠道，也不能把订阅凭据直接转换成 API Key。

Coding Plan 的当前边界

“OpenAI Codex · 本地订阅观测”只针对 OpenAI Codex。其他厂商 Coding Plan 不能通过选择它自动接入；需要兼容的 Codex Profile、明确的 provider 标识与真实额度观测。当前仓库的自动化测试不等于真实厂商账号验收。

04 / ACCEPT

验收清单

依照证据判断通过，不以“已创建”或“已登记”代替成功。

01
服务可用

控制台 /api/health 返回 {"ok":true}；网关 /healthz 返回 ok。

02
项目与权限

能创建项目、设置工作目录，并以有权限的账号查看项目。

03
真实模型请求

渠道测试成功，网关返回模型响应，日志和用量数据能对上同一次调用。

04
本地订阅观测

Codex 运行后出现会话记录；该记录不混入网关账单。

05
任务连续性

监督任务能启动、完成；故障切换场景可在任务历史中核对会话 ID、来源和目标资源。

06
资源与路由视图

“资源”显示已登记连接及渠道的实际状态；“路由”按项目给出候选预览。未知额度应保持未知。

07
模型与价格

“模型广场”显示模型目录；价格审批和账单中的金额应来自已生效价格，未定价的请求不应被标成免费。

08
成员、审计与对账

用不同角色检查页面权限；创建、修改和撤销操作在审计日志中有记录。对账工单仅在有待处理事实时出现。

05 / SUPPORT

常见问题

添加连接后为什么仍不能调用模型？

“我的连接”主要记录资源身份和观测状态。API 模型调用需要在“渠道管理”保存上游凭据与模型，再创建 Nexus 下游密钥，并启动网关。

为什么没有项目用量或任务？

确认项目配置了与 Codex 实际工作目录一致的路径，Observer 已应用配置且同步成功。普通 Codex 会话只会被观测；只有通过 npm run nexus -- codex 注册的任务才进入监督页面。

为什么 /v1/models 返回 401？

网关要求 Nexus 下游 API 密钥。先在控制台“API 密钥”创建，再以 Authorization: Bearer ... 发送请求。

为什么 Coding Plan 没有自动切换？

检查是否存在两个独立登录的兼容 Profile、Supervisor 配置、项目路由策略和最新官方额度观测。未知额度不会被当成可用额度。

发现手册与实际行为不一致？请在 GitHub Issues 提供页面、操作步骤和脱敏后的结果。
