01 / GET STARTED

从项目开始

登录控制台后，先创建一个项目。项目是资源归属、成员访问、用量查看和任务策略的共同入口。

  1. 登录工作空间

    使用管理员提供的控制台地址和账号登录。如果你是在本机运行源码，登录信息来自本地开发配置；部署说明见本地部署。

  2. 创建项目

    打开“项目”→“创建项目”，填写名称。要将本地 Codex 会话归入此项目，再填写代码工作目录的绝对路径；可以每行配置一个路径。

  3. 选择接入方式

    需要让应用调用模型，配置API 渠道。使用本机 Codex，添加订阅观测连接。需要由 Nexus 管理编程任务，再配置任务监督。

不需要一次完成所有设置

只使用网关 API 时，可以先不配置 Codex；只想查看 Codex 本地用量时，也不需要创建网关 API 密钥。

我是应用开发者

从“渠道管理”配置上游模型，再创建 Nexus API 密钥，把网关地址接入自己的客户端。

02 / GATEWAY API

通过网关调用模型

Nexus API 网关提供兼容 OpenAI 的调用入口。上游模型凭据用于访问供应商；Nexus API 密钥用于你的应用访问网关，两者不要混用。

01

配置上游渠道

控制台 → 渠道管理

在本机控制台填写供应商的接口地址、协议、API Key，并按每行一个填写该渠道支持的模型 ID。 保存后可在页面检查上游连接；连接测试只验证第一个模型。渠道决定网关能够调用哪些模型；仅在“我的连接”里登记一条 API 连接，不会生成可用渠道。

凭据位置本地桌面模式可加密保存上游密钥。其他部署方式由管理员按独立密钥服务的要求配置。
02

创建 Nexus API 密钥

控制台 → API 密钥

为应用创建独立下游密钥，并按需要设置权限范围与过期时间。只在创建时安全保存完整密钥；请求中使用 Authorization: Bearer YOUR_NEXUS_API_KEY。

03

在客户端使用网关地址

控制台 → 开发文档

“开发文档”显示当前部署配置的网关 Base URL。将它设为兼容 OpenAI 客户端的地址，填入 Nexus API 密钥和已配置的模型 ID。本机默认网关地址是 http://127.0.0.1:8080/v1；本地使用前需启动 npm run gateway:local。 

curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Authorization: Bearer YOUR_NEXUS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"YOUR_CONFIGURED_MODEL","messages":[{"role":"user","content":"Hello"}],"max_tokens":32}'

上方命令适用于 Bash。Windows PowerShell 可以将同样的 JSON 请求通过 Invoke-RestMethod 发送；真实请求会消耗上游额度。

04

查看请求和用量

控制台 → 请求日志 / 用量与计费

“请求日志”用于查看调用结果与错误；“用量与计费”按请求、项目等维度展示可归属的用量。价格来源不明确时，费用显示为未知，不会被当作免费。

03 / LOCAL CODEX

查看 Codex 订阅使用

Nexus 读取本机 Codex 会话中允许的用量字段，并单独展示账户和官方额度观测。Codex 继续使用自己的登录，不通过 Nexus 网关发送订阅请求。

开始前

在运行 Nexus 的电脑上，先通过官方 Codex 完成登录；在“项目”中配置实际代码工作目录。Nexus 页面不要求你粘贴 Codex 凭据。

  1. 添加 Codex 连接

    进入“我的连接”→“添加连接”，选择“OpenAI Codex · 本地订阅观测”。官方 OpenAI Codex 使用默认供应商标识 openai；可按需要绑定项目。

  2. 启用本地同步

    打开连接详情，在“本地同步配置”中确认 Codex 会话目录并应用 Observer 配置。Observer 会定期读取本机会话，也可以在连接详情中手动请求立即同步。

  3. 查看账户与项目用量

    连接详情显示最近的账户、额度和同步状态；“项目”或“用量与计费”中的项目分析显示归属到工作目录的本地会话用量。历史观测不会因后来修改目录而自动移动。

本地观测的 Token 不是官方账单，也不能推算 Coding Plan 的剩余额度；订阅使用不会计入网关请求账单。细节见 Observer 运维说明 ↗。

04 / CODING TASKS

监督持续编程任务

给 Nexus 一个明确的编程目标，它会在本地运行 Codex，并在任务页记录进度、当前资源、会话和交接历史。任务页不是待办清单； 平常直接运行的 Codex 会话只进入本地用量观测，不会自动变成受监督任务。

开始前：准备本地运行环境

在“项目”中登记实际代码工作目录，并为候选账户创建连接。每个候选账户需要独立的 Codex Profile 和登录目录； 管理员还需在本机配置项目、连接与 Profile 的映射，设置 NEXUS_SUPERVISOR_CONFIG， 并启动启用了任务监督的 Observer。仅添加连接或保存页面策略，不会自动创建 Profile 或启动任务。

  1. 为项目设置路由策略

    打开控制台“任务”页，选择项目，点击“编辑策略”→“添加候选资源”。为每个候选项选择连接，填写与本地配置一致的 Profile 引用，并设置优先级、能力及按需使用的模型限制。保存后可在下方“资源池”查看哪些候选资源可用， 以及不可用的原因。自动切换只在确认资源耗尽或不可用时执行；额度未知不会被当作可用。

  2. 通过 Nexus 启动任务

    展开页面的“从本地启动任务”，复制命令，在已登记的代码工作目录里运行。将 PROJECT_ID 换成所选项目 ID，并把示例目标改成你希望 Codex 完成的工作。--persist-context 表示同意保存本次任务目标和必要的交接上下文；任务由本地 Observer 接手执行。若代码目录不是 NexusAPI 仓库， 请按下方运维说明使用 Nexus 脚本的绝对路径。 

    npm run nexus -- codex --project PROJECT_ID --goal "完成当前编程任务" --persist-context
  3. 查看任务与资源状态

    回到“任务”页查看任务状态、当前连接、会话连续性、资源切换和观测用量。页面可见时每 7 秒刷新，也可以手动刷新。 “项目任务 0”表示该项目尚未通过 Nexus 启动托管任务；“可用资源 / 全部 0 / 0”表示策略中还没有可展示的候选资源， 不代表项目没有连接。普通 Codex 对话不会自动出现在此列表。

  4. 继续或恢复任务

    任务运行中可在卡片上请求“切换资源”，Nexus 会等待安全边界并尽量保留原会话；暂停或失败后， 先检查工作目录和上次执行结果，再点击“恢复任务”。如果任务已完成，还想沿用原目标继续工作， 在本地终端提交新指令。TASK_ID 可从任务卡片或下方状态命令获取。 

    npm run nexus -- status --project PROJECT_ID
npm run nexus -- continue --project PROJECT_ID --task TASK_ID --instruction "继续完成剩余工作"

独立 Profile 的准备方法、恢复规则及安全边界见 任务级资源切换说明 ↗。

05 / WORKSPACE

控制台功能导览

页面展示的是不同来源的事实。了解每个页面负责什么，可以更快找到需要配置或查看的内容。

01
项目

组织工作目录、项目成员与项目分析。Codex 本地会话按工作目录归属；网关请求按自身项目归属记录。

02
渠道管理 / API 密钥

前者配置网关要调用的上游模型；后者签发你的客户端调用 Nexus 网关所用的下游密钥。

03
我的连接 / 资源

“我的连接”登记账户和连接并查看观测；“资源”汇总渠道和连接的类型、健康、额度与配置状态。

04
路由 / 任务

“路由”展示按项目的候选预览；“任务”管理本地编程任务策略和执行历史。网关实际选路以请求时的签名快照为准。

05
请求日志 / 用量与计费

查看网关请求及其用量，也可在项目分析中查看单独的 Codex 本地观测；两种来源不混算费用。

06
模型广场 / 价格审批

查看模型目录与价格治理信息。目录存在不代表当前项目已有可调用渠道；未知价格保持未知。

07
成员与角色 / 审计日志 / 对账工单

管理员在这些页面管理访问权限、检查操作记录，并处理出现的对账事项。

SUBSCRIPTIONS

管理不同服务的订阅与额度

在“我的连接”登记订阅服务，绑定项目，并按该产品实际支持的方式查看额度或配置 API。

  1. 选择你的服务

    点击“添加连接”，选择订阅类型及产品。目录包括 Codex、Claude Code、Gemini、Copilot、Cursor、Windsurf、Kiro、JetBrains AI、Trae、Qwen、Kimi、GLM、MiniMax、百炼、火山方舟、腾讯、DeepSeek、Grok 和 Perplexity。详情会显示官方使用说明和实际接入能力。

  2. 绑定项目与监控账号

    一个项目可关联多个连接。Codex 使用原生账户同步；其他支持监控的产品可在详情中导入 CodexBar 的 dashboard-v1 JSON，或同步管理员配置的 CodexBar 服务。预览后明确选择对应账号；同一供应商的不同账号不会自动合并。

  3. 查看账号池

    打开“资源”查看账号池和每个额度窗口。有效观测会标出使用比例、重置时间和数据来源；过期、登录异常、耗尽与未知状态分别显示。页面可见时每 30 秒重新读取已保存的数据，外部采集需要在连接详情执行同步。重置时间到达也需重新观测，不能直接视为额度已恢复。

  4. 需要 API 时配置渠道

    “渠道管理”中的接入模板可填写官方 API 地址，或连接你已部署的 CLIProxyAPI、New API、Sub2API 等兼容服务。填写该服务的访问密钥与实际模型 ID（每行一个），再按 API 章节创建 Nexus 密钥。不同订阅的登录凭据与开放平台 API Key 不可互换；仅限编程工具的套餐按官方说明在原生工具中使用。

监控能力以详情为准

登记成功不代表可自动读取额度或调用模型。CodexBar 报告是第三方监控数据，不会转化为 Nexus 钱包余额，也不会直接决定任务调度。没有兼容采集器的产品保留登记及官方使用指引。

具体产品能力见 服务覆盖说明，管理员配置见 多服务监控配置。

AGENT USAGE

查看不同 Agent 工具的会话与用量

在同一个项目中使用多个 Agent 时，按工具区分记录；自定义模型不会改变工具身份。

  1. 登记工作目录

    在“项目”中填写实际代码目录。会话根据工具日志报告的工作目录归属到项目，绑定连接不会自动拦截对话。

  2. 开启自动发现

    本机管理员进入“用量与计费”，展开“Agent 工具采集”，启用“自动发现本机工具记录”。确认后台运行后正常使用工具；后台每次轮询都会发现新安装的受支持工具日志。

  3. 按工具完成接入

    Codex、Claude Code、Gemini CLI、Qwen Code、Cline、Roo Code、兼容版 Kilo 扩展、Copilot CLI 和 Kimi CLI 支持原生日志；OpenCode 使用导出 JSON；Cursor 使用官方 Hook。其余工具可通过通用元数据接口接入，工具 ID 可扩展，无需修改数据库。

  4. 查看采集状态和记录

    面板显示发现来源、缺失路径、同步状态和历史会话。点击“立即同步”，完成后刷新；在项目分析选择“工具来源”并展开会话。日志缺少工作目录时，可为单个任务来源手动指定目录。

接入能力以工具实际提供的数据为准

不提供可读日志的工具需要配置 Hook、遥测或导出，安装工具本身不代表已接入。仅报告活动、不报告 Token 的记录显示未知；不会推算 Token、保存聊天正文或产生钱包扣费。网关请求和订阅剩余额度分别查看。

PAYMENTS

购买平台套餐与查看支付结果

“用量与计费”管理 NexusAPI 自身的平台套餐、托管额度订单和账本。Claude、ChatGPT 等第三方订阅仍在各自官方平台购买。

  1. 查看可购套餐

    进入“用量与计费”，查看管理员已发布的套餐、价格及币种。没有套餐或商户尚未配置时，页面会说明当前无法购买的原因。当前在线购买仅支持平台套餐，不提供钱包充值；普通 BYOK 调用与上游订阅费用单独核算。

  2. 进入托管收银台

    有购买权限的成员选择套餐后，跳转到 Stripe 完成付款。测试模式会明确标识；真实付款须由管理员配置正式商户。银行卡等付款信息在 Stripe 收银台填写。

  3. 确认订单状态

    回到 NexusAPI 后刷新订单。回到页面不表示支付成功；系统收到并验证支付通知后才会更新订单、激活对应权益并写入账本。通知延迟时请保留订单号，稍后刷新，不要重复购买。

管理员请阅读 Stripe 支付配置，完成密钥、套餐发布和回调设置。

06 / CONCEPTS

几个容易混淆的概念

“添加连接”是资源登记。能否真正调用或运行，取决于渠道、凭据、Profile 和最新状态是否具备。

项目

管理访问范围、代码目录、用量归属和任务策略的工作单元。

渠道

网关使用的上游接口、模型与凭据配置。API 模型请求从这里进入。

连接

描述一个账户或资源的归属、类型及观测状态。登记本身不会自动启用模型调用。

连接器

设计上是运行在本机或私有网络、执行请求并报告状态的程序。当前“本地连接器”“私有网络连接器”选项主要用于登记，不会在添加时自动安装运行器。

Nexus API 密钥

你的客户端访问 Nexus 网关所用的下游凭据，与供应商上游密钥不同。

Codex Profile

任务监督使用的独立 Codex 配置与登录目录，不等同于网关 API 渠道。

其他厂商 Coding Plan

为其他 Coding Plan 选择其对应产品，不要登记为 Codex。连接详情会说明原生工具、独立 API 与第三方额度监控的区别；受监督执行仍需相应的兼容 Profile 和可信额度观测。

07 / SELF HOSTING

在本机部署 NexusAPI

这部分面向自行运行源码的管理员。如果你已经有可登录的 Nexus 控制台，可以直接从开始使用阅读。

环境要求

Node.js 24、npm、PostgreSQL 14+ 和 Redis 6+。本地可以用 Docker 启动数据库与 Redis；Go 网关使用仓库指定的 Go 版本。

  1. 获取代码与配置 
    git clone https://github.com/Wuysau/NexusAPI.git
cd NexusAPI
npm ci
Copy-Item .env.example .env.local

    最后一条是 Windows PowerShell 命令；macOS/Linux 使用 cp .env.example .env.local。编辑本地配置，至少设置开发账号的 DEV_ADMIN_PASSWORD 与 DEV_VIEWER_PASSWORD。真实配置不会提交到仓库。

  2. 初始化并运行控制台 
    docker compose up -d postgres redis
node --env-file=.env.local scripts/db-migrate.mjs
npm run seed:dev
npm run dev

    默认控制台地址是 http://127.0.0.1:3000。Windows 在数据库已启动、迁移已完成后也可用 npm run dev:local 日常启动。

  3. 按需启动网关

    本地 API 调用还需要在 .env.local 中设置 NEXUS_DESKTOP_ORIGIN、CONTROL_PLANE_URL、NEXT_PUBLIC_GATEWAY_BASE_URL，并为 SNAPSHOT_SIGNING_KEY 与 GATEWAY_INTERNAL_TOKEN 分别设置随机值。保存本地渠道密钥后，在另一个终端运行 npm run gateway:local。

生产部署有独立的数据库角色、密钥服务和迁移要求；请阅读仓库的 README 与 运维文档。不要把桌面本地模式作为生产配置。

HELP

常见问题

为什么添加了 API 连接，仍无法调用模型？

“我的连接”保存资源登记。请到“渠道管理”配置并启用上游模型渠道，再创建 Nexus API 密钥，通过独立网关发起调用。

Codex 或 Claude Code 已运行，为什么项目中没有本地用量？

检查项目工作目录是否与 Codex 会话目录匹配，连接详情中的 Observer 配置是否已应用、同步是否成功。修改工作目录不会自动重新归属已有历史记录。 Claude Code 需另行配置 Observer 的 claudeSources，指向本机 .claude/projects 或具体项目子目录， 然后在项目分析中选择“Claude Code · 本地观测”。直接调用外部自定义渠道不会生成 NexusAPI 网关请求。 Claude Code 采集配置。

为什么普通 Codex 会话没有出现在任务页？

任务页只监督通过 Nexus CLI 登记启动的任务。普通 Codex 会话可以被 Observer 观测，但不会获得 Nexus 的任务策略和切换能力。

为什么资源状态显示“未知”？

Nexus 不会凭连接名称猜测额度、价格或健康状态。缺少新鲜可信的观测时，状态保持未知；部分路由与任务选择因此不会自动启用。
