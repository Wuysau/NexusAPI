# CC Switch research for Nexus conversation continuity

Reviewed on 2026-09-24: the [failover manual](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/en/4-proxy/4.3-failover.md), [`provider_router.rs`](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/proxy/provider_router.rs), [`failover_switch.rs`](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/proxy/failover_switch.rs), [`services/proxy.rs`](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/proxy.rs), [`services/config.rs`](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/config.rs), [`codex_config.rs`](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/codex_config.rs), the [unified Codex history guide](https://github.com/farion1231/cc-switch/blob/main/docs/guides/codex-unified-session-history-guide-en.md), and release notes [3.17](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v3.17.0-en.md), [3.20](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v3.20.0-en.md), and [3.20.1](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v3.20.1-en.md). These are design references; Nexus does not copy their code.

The reusable patterns are an ordered provider queue, per-provider circuit state, switch deduplication, a separate live configuration with a recoverable original, and history/provider classification independent of the conversation body. CC Switch's failover manual shows same-request retry after a provider error. Nexus instead excludes an exhausted API channel for subsequent requests, because a coding turn may already have made file, command or external changes. CC Switch 3.20 explicitly excludes official Codex account cards from its ordinary proxy retry queue because inbound authorization belongs to the original account. Nexus preserves that boundary: official subscription changes happen through a local isolated tool profile.

The unified-history guide describes `model_provider` classification in session JSONL and SQLite state, backup before metadata edits, and the inability to decrypt some backend-private `encrypted_content` across providers. Nexus currently leaves session metadata untouched and asks the target Codex runtime to resume the exact thread ID without starting a turn. A verified missing rollout allows task context handoff; an ambiguous result pauses. This is narrower than a general history migration but avoids editing live user history or claiming continuity without verification.

CC Switch 3.20's multiple-account handling also illustrates why one OAuth login must never be treated as another account's reusable HTTP authorization. Nexus's connection/profile references stay in the control plane while actual Codex login files remain in separately enrolled local homes. CC Switch 3.20.1's config-only third-party provider switch reinforces separating provider configuration from official `auth.json`. Nexus currently does not take over live Codex or Claude config, so config backup/restore is deferred until that mutation exists.
