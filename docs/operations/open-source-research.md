# Open-source integration decisions

Research dates: 2026-09-29 through 2026-10-03. These are independently implemented design ideas; no third-party project source has been copied into NexusAPI.

| Primary source | Useful pattern | NexusAPI implementation |
| --- | --- | --- |
| [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI) and its [configuration](https://github.com/router-for-me/CLIProxyAPI/blob/main/config.example.yaml) | Compatible provider endpoint behind independently managed accounts | Existing gateway plus explicit proxy channel templates; provider authentication stays with the external service. |
| [CodexBar](https://github.com/steipete/CodexBar) and [dashboard-v1](https://github.com/steipete/CodexBar/blob/main/docs/dashboard-api.md) | Multiple quota windows, freshness and account-specific monitoring | Sanitized dashboard snapshot importer and configured read-only collector bridge; explicit account selection, expired/unknown state, no financial or routing authority. |
| [cc-switch](https://github.com/farion1231/cc-switch) | Clear provider setup and compatible endpoint presets | Capability-based product catalog and channel templates; no automatic rewriting of users' client configuration. |
| [New API](https://github.com/QuantumNous/new-api) | Separate plan catalog, orders and hosted checkout | Published server-side plans and Stripe PaymentProvider integrated into Billing, preserving NexusAPI's existing immutable ledger. |
| [Sub2API](https://github.com/Wei-Shaw/sub2api) | Account status and pooled capacity visibility | Per-product account counts and separate monitoring of healthy, near-limit, exhausted, disabled and unknown states. |
| [LiteLLM routing](https://docs.litellm.ai/docs/routing) and [health checks](https://docs.litellm.ai/docs/proxy/health) | Error-specific cooldown; lightweight public readiness distinct from model diagnostics | Channel/model cooldown without replaying the current call; request errors do not poison shared health; bounded live dependency probes and aggregate public breaker counts. |
| [Portkey automatic retries](https://portkey.ai/docs/product/ai-gateway/automatic-retries) | Interpret provider retry hints with bounded waiting | Parse only normalized retry timing, cap it at 60 seconds, and apply it to later request routing. NexusAPI's stricter execution/replay boundary remains authoritative. |
| [LiteLLM rate limits](https://docs.litellm.ai/docs/proxy/users) and [Portkey retry timing](https://portkey.ai/docs/product/ai-gateway/automatic-retries) | Coordinate rate capacity across instances and communicate known recovery time | Redis server time drives shared RPM/TPM buckets. Production rate-backend failures reject admission before budget reservation; only explicit development/test permits reduced local limits. Determinate temporary exhaustion returns rounded-up `Retry-After`, without automatic inference replay. |
| [Bifrost provider routing](https://github.com/maximhq/bifrost/blob/dev/docs/providers/provider-routing.mdx) | Separate governance constraints, routing and health signals | Existing hard authorization filters remain mandatory before weighted selection. Connector management readiness intersects local model reports with currently eligible channel approvals, independently from transport online status; channel resources retain their own model scope. No enterprise routing implementation is copied. |
| [Bifrost observability](https://github.com/maximhq/bifrost/blob/dev/docs/features/observability/default.mdx) and [deployment metrics](https://github.com/maximhq/bifrost/blob/dev/docs/deployment-guides/helm/plugins.mdx) | Export operational metrics for a separate monitoring system | Optional authenticated Prometheus endpoint with fixed aggregate counts and timing. No content logging or user-controlled metric labels; only measurements actually wired into the request path are exposed. |
| [cloudflared backoff lifecycle](https://github.com/cloudflare/cloudflared/blob/master/retry/backoffhandler.go) | Bound reconnect attempts and allow cancellation during waits | Connector polling and renewal use independent bounded backoff within the active lease. A separate lease deadline cancels work and returns failure to the process manager. Model execution, result upload and one-time pairing are never automatically replayed. |
| [Bifrost provider I/O design](https://github.com/maximhq/bifrost/blob/dev/AGENTS.md) and [Caddy HTTP transport](https://github.com/caddyserver/caddy/blob/master/modules/caddyhttp/reverseproxy/httptransport.go) | Apply deadlines to the relevant network operation while accommodating long streams | Shared downstream write budgets cover buffered inference and SSE. Successful intermediate flushes clear their deadline so HTTP/2 remains healthy during durable terminal persistence; failed delivery never replays inference or rewrites completed usage. |
| [Envoy xDS validation and TTL](https://www.envoyproxy.io/docs/envoy/latest/api-docs/xds_protocol#ttl) | Validate received configuration before replacement and bound how long it remains usable | Require a complete single-document response within 8 MiB; check signed expiry at receipt and after verification, and recheck platform directory freshness during authentication. Rejected candidates preserve the previous generation's original expiry. NexusAPI keeps its signed-envelope protocol and existing explicit legacy BYOK degradation policy. |
| [Envoy versioned resource indexes](https://github.com/envoyproxy/go-control-plane/blob/main/pkg/cache/v3/resources.go) | Prepare lookup indexes within a configuration generation | Build a private API key hash index after signed snapshot verification and publish it with that generation. Each request retains current key-state and permission checks; no authentication result is cached across refreshes. NexusAPI preserves its first-match duplicate rule. |
| [Envoy xDS subscriptions](https://www.envoyproxy.io/docs/envoy/latest/api-docs/xds_protocol#unsubscribing-from-resources) | Track current interest separately from retained configuration | Isolate platform-directory refresh from the serial tenant sweep. A fresh directory restricts scheduled tenant refresh to known scopes with usable keys; missing/expired directory state preserves conservative refresh. Retain last-good states and existing BYOK semantics rather than silently introducing eviction. |
| [LiteLLM provider-directed cooldown](https://github.com/BerriAI/litellm/pull/5358) | Use upstream retry hints when deciding later model availability | Extend the existing cooldown parser through the local connector with a bounded numeric metadata field. Keep headers and error bodies local, cap the hint again at the Gateway, and retain the existing no-replay and per-channel/model breaker rules. |
| [Go singleflight](https://pkg.go.dev/golang.org/x/sync/singleflight) | Share the result of concurrent duplicate work, including errors | Per-scope snapshot refreshes share a typed in-progress result with independently cancelable waiters. Completion removes it immediately; no negative TTL delays recovery or changes signed validity. The original caller still owns the fetch context. |
| [Envoy timeout responsibilities](https://www.envoyproxy.io/docs/envoy/latest/faq/configuration/timeouts) | Distinguish overall, individual-attempt and idle budgets | Enforce NexusAPI's existing whole-attempt deadline through header wait and stream consumption, under the parent total deadline. Keep separate idle/write limits and strict replay rules. NexusAPI's attempt limit continues after response headers. |
| [LiteLLM parameter handling](https://docs.litellm.ai/docs/completion/drop_params) | Reject unsupported input by default instead of silently changing its meaning | Validate stopping and sampling at ingress, then check adapter request fidelity before credentials or billing. Preserve explicit modern output-limit fields, with documented Ollama/DeepSeek mappings selected from signed provider facts. Native adapters reject unimplemented semantic translations; compatible custom models retain parameter passthrough. No automatic parameter-dropping option is enabled. |

Repository licenses are governed by their own LICENSE files. Integration here is through documented protocols and original code; listing a project does not relicense its code. NexusAPI remains MIT. OAuth impersonation, copying browser cookies and treating subscription pools as unlimited API credits were not adopted.

[Vercel AI SDK's signal composition](https://github.com/vercel/ai/blob/main/packages/ai/src/util/merge-abort-signals.ts) combines caller cancellation with operation timeouts. NexusAPI uses the same native Node primitive for console connector tests, forwarding an incoming cancellation through the Gateway fetch and response-body read while retaining the existing 60-second deadline. Deployment proxies still determine whether a browser disconnect reaches the control plane; a canceled operation does not undo already incurred usage.

The connector panel applies the corresponding [AI SDK stop lifecycle](https://ai-sdk.dev/docs/advanced/stopping-streams): an explicit cancel action aborts the browser request, and unmount cleanup aborts outstanding tests and polling. Request ownership checks prevent a canceled test's delayed result or cleanup from overwriting a later test. Separate connection keys reset private input state; already dispatched pairing mutations retain their original server-side behavior.

[Ky's body-read handling](https://github.com/sindresorhus/ky/blob/main/source/core/Ky.ts) distinguishes a failed successful-response body from optional error-response details. NexusAPI applies that distinction to its existing browser helper: failed JSON reads reject, cancellation retains its `AbortError`, and malformed content produces a fixed local error. Explicit no-content statuses remain valid. No HTTP client dependency or automatic mutation retry is introduced.

[TanStack Query's query keys](https://tanstack.com/query/latest/docs/framework/react/guides/query-keys) bind results to the variables that produced them. NexusAPI applies that principle to `useApiData` using its existing request URL: changing a project or filter resets all visible result state before children commit, and disabling a query clears it. Refreshing the same URL retains its last-good result on failure. This needs no shared query cache or new dependency.

[SWR's read/mutation ordering](https://github.com/vercel/swr/blob/main/src/index/use-swr.ts) prevents older reads from replacing newer operation results. NexusAPI uses separate session-read and auth-operation identities within its existing provider. Logout, login and reauthentication invalidate obsolete reads; a superseded reauthentication rejects before its success callback can retry an old action. Dispatched auth POSTs retain their server-side behavior and are not replayed.

[OpenAI Node SDK v7.27.0's incremental line decoder](https://github.com/openai/openai-node/blob/v7.27.0/src/internal/decoders/line.ts) handles a trailing CR immediately and suppresses its optional following LF. NexusAPI applies that principle in its own buffered Go SSE reader, supporting all three line endings from the [SSE specification](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream). Bounded chunk scanning avoids the measured overhead of a per-byte prototype. The existing raw event limit, incomplete-event discard, provider completion checks and no-replay rule remain authoritative; a blank-line CR reserves one possible LF within the size limit.

[eventsource-parser's initial BOM state](https://github.com/rexxars/eventsource-parser/blob/c3729207bf7bc71297cc4485629633b3bce2fb05/src/parse.ts) separates stream initialization from later chunks. NexusAPI applies the [SSE rule for one leading UTF-8 BOM](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation) directly to its owned byte stream after raw-size accounting. Only the first line may lose one prefix; later markers and payload characters remain intact. This original Go change prevents silent first-content/usage loss without adding the JavaScript parser or weakening unknown-usage reconciliation.

[cloudflared's origin CA configuration](https://developers.cloudflare.com/tunnel/reference/origin-parameters/#capool) extends system trust for a private HTTPS origin while verifying its certificate. NexusAPI applies its existing local `caFile` bundle to the connector's remote and local HTTPS clients, preserving IP/DNS identity and validity checks. Separate TLS configuration clones preserve HTTP/2 negotiation without sharing mutable transport settings. The local endpoint remains an explicitly configured private IP with fixed model/chat paths; no origin-name override, verification bypass or general proxy capability is added.

[OpenAI's typed usage contract](https://github.com/openai/openai-python/blob/becc1d20eed83c1b8d85e15dc131a372d9dc7813/src/openai/types/completion_usage.py#L56-L67) declares an integer total, and its [stream options contract](https://github.com/openai/openai-node/blob/11b9283f2a22737e273ccc1593d01af5cf584a0b/src/resources/chat/completions/completions.ts#L1104-L1113) describes final whole-request usage that may be absent after interruption. [LiteLLM's cumulative usage helper](https://github.com/BerriAI/litellm/blob/5724117116102665495b9bad0c998fd210cdee06/litellm/litellm_core_utils/streaming_handler.py#L2415-L2454) likewise tracks the latest reported usage. NexusAPI validates the supplied total in its existing wire decoder before merging observations. A malformed later report fails the stream and leaves reliable earlier counts as partial evidence. Strict runtime rejection, optional nullable counters, unknown execution and reconciliation without guessed counts or prices remain NexusAPI's own policy.

[Google GenAI's optional integer usage total](https://github.com/googleapis/python-genai/blob/618f0aa89c7fa61be973fabfa5747fb93a21b1bf/google/genai/types.py#L8561-L8563) separates a missing report from a reported count, matching the [Gemini REST usage schema](https://ai.google.dev/api/generate-content#UsageMetadata). NexusAPI also validates `totalTokenCount` before updating its native stream observations. This prevents a malformed report followed by partial metadata from restoring old counters as completed execution. The Gateway keeps its existing int64 observer range, nullable reports and reconciliation rules; SDK type annotations are not assumed to define its runtime validation policy.

Anthropic's [Usage](https://github.com/anthropics/anthropic-sdk-python/blob/18f25547f20cf5f01da69ac611e700e3bc9ebf21/src/anthropic/types/usage.py) and [MessageDeltaUsage](https://github.com/anthropics/anthropic-sdk-python/blob/18f25547f20cf5f01da69ac611e700e3bc9ebf21/src/anthropic/types/message_delta_usage.py) declare the same consumed integer counters across initial and cumulative reports, with optional cache and output details. NexusAPI uses a shared private wire shape to validate those counters before either report updates stream state. Malformed cache, thinking or delta input reports cannot become completed usage through a later partial update. The existing inclusive input formula, nullable observations, unknown total and negative-counter guards retain their current behavior; no SDK code or new financial rule is imported.

Compatible message history follows the same parameter-fidelity principle: preserve caller-supplied `reasoning_content` needed for [DeepSeek tool follow-ups](https://api-docs.deepseek.com/guides/thinking_mode/), and map it to the `reasoning` field in [Ollama's OpenAI protocol](https://github.com/ollama/ollama/blob/main/openai/openai.go). Native adapters reject history they cannot translate. NexusAPI does not synthesize placeholder reasoning or infer thinking settings from model names. Two-turn HTTP and standalone-connector tests verify the original history and tool results survive the round trip.

The same principle applies to output: [OpenAI structured-output refusals](https://developers.openai.com/api/docs/guides/structured-outputs) are preserved as typed Chat fields and Responses content/events, with assistant history available for continuation. A normal refusal retains completion and reliable usage facts; it is not an empty answer or a transport failure. Existing output bounds, privacy and replay rules still apply.

[LiteLLM's Anthropic image translation](https://github.com/BerriAI/litellm/blob/cede93e826b2c352de62dcc3bbe725f9728d0352/litellm/litellm_core_utils/prompt_templates/factory.py#L828) illustrates the need to translate canonical media parts before provider execution. NexusAPI independently converts a documented subset of `image_url` references/data into native image blocks, preserving tool relationships and validating unsupported semantics before credential/budget access. It performs no media download or local file read; system/developer content that cannot survive the current text conversion is rejected.

[OpenAI's request-ID metadata](https://github.com/openai/openai-python/blob/becc1d20eed83c1b8d85e15dc131a372d9dc7813/src/openai/_models.py#L133-L143) and [Anthropic's corresponding metadata](https://github.com/anthropics/anthropic-sdk-python/blob/18f25547f20cf5f01da69ac611e700e3bc9ebf21/src/anthropic/_models.py#L125-L132) support provider debugging separately from response content and token usage. NexusAPI preserves that separation when projecting terminal facts: reported identifiers exceeding its existing 512-code-point event limit are omitted from all durable projections, while compliant values and reliable usage remain unchanged. The limit is NexusAPI's contract policy; the SDKs are not claimed to enforce it. No provider identifier is truncated, hashed or substituted for the Gateway's authoritative request identity.

## External contracts

- [Stripe Checkout fulfillment](https://docs.stripe.com/checkout/fulfillment): complete orders via verified server callbacks, not browser redirects.
- [Stripe webhook signatures](https://docs.stripe.com/webhooks/signature): verify the original raw payload and timestamp; keep settlement idempotent.
- Provider-specific links are retained in `src/lib/subscriptions/catalog.ts` and the subscription coverage document. Source endpoints, product availability and limits may change; no current model prices are hardcoded into payment plans.

The scope is operational visibility and authorized access within the existing control plane. Collectors and payment merchant credentials must be configured by the operator. Automated mocked-protocol tests do not establish that every vendor account or a live merchant charge was exercised.
